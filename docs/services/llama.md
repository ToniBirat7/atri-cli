# llama.cpp Runtime

The llama.cpp runtime is the model inference layer. It serves Gemma 4 through an OpenAI-compatible HTTP API and supports tool calling through the Jinja chat template.

## What It Does

- Loads the GGUF model from the local model volume
- Serves chat completions over HTTP
- Accepts system prompts generated by the orchestrator
- Emits model responses and tool calls for the agent loop to process

## Why It Matters

The orchestrator depends on llama.cpp for local inference and tool-call generation. Gemma 4 is used in a way that keeps the policy decision in the orchestrator and the model focused on response generation and tool selection.

## Template Behavior

The runtime is started with Jinja support so the chat template can place system content in the system turn and inject tool declarations correctly. That keeps prompt policy and tool registration behavior aligned with the model’s expected input format.

## Placement in the Stack

- The frontend never talks to llama.cpp directly
- The orchestrator is the only service that calls the model server
- MCP tools are only reachable through the orchestrator agent loop

## Operational Notes

- Keep the model file on a persistent read-only volume
- Align the model path in compose with the actual GGUF filename
- Ensure the model server is healthy before starting the orchestrator
